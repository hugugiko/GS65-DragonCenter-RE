# EC 寄存器表 —— MSI GS65 Stealth 9SE（MS-16Q4）

[English](../en/02-ec-register-map.md) | **简体中文**

> **范围**：这是一张**机型相关的观测表**，只在单台机器上校准过，不是 MSI 官方规范，
> 不保证适用于其他机型或固件版本。
>
> **数据来源**：这些数值由私有校准工具在运行时读写嵌入式控制器得到。该工具的源码和
> 二进制文件**不在本仓库中分发**，这里只记录由此得出的互操作性事实。
>
> **风险**：写 EC 寄存器可能改变温度墙、风扇行为、充电行为以及其他由固件管理的状态。
> 写入错误可能导致系统不稳定或硬件损坏。使用风险自负。请阅读 [NOTICE.md](../../NOTICE.md)。

## 1. 目标机器

| 项目 | 值 |
|---|---|
| 机型 | MSI GS65 Stealth 9SE |
| 主板 | MS-16Q4 |
| EC 固件 | `16Q4EMS1.1100712` |
| BIOS | `E16Q4IMS.118` |
| EC 访问方式 | WinIo 驱动（`WinIo64.sys`），I/O 端口 `0x62`/`0x66` |
| EC 访问命令 | 读 `0x80`、写 `0x81`（WinIo 封装层的命令码） |
| 校准所用系统 | Windows 11 |

本机存在 ACPI WMI 接口（`root\WMI` 下的 `MSI_*` 类），但实测表现不可靠（疑似固件缺陷），
因此下表中的风扇、温度和电池数值均通过 EC 直接访问获得。

## 2. 读取寄存器

| 偏移 | 含义 | 观测值 | 状态 |
|---|---|---|---|
| `0x68` | CPU 实时温度（°C） | 例如 62，随负载变化 | ✅ 已验证 |
| `0x80` | GPU 实时温度（°C） | 例如 64 | ✅ 已验证 |
| `0x71` | CPU 风扇当前档位（原始值） | 负载下 60 → 70 | ✅ 已验证 |
| `0x89` | GPU 风扇当前档位（原始值） | 例如 70 | ✅ 已验证 |
| `0xEF` | 电池充电阈值 | `0xE4` = 充到 100% | ✅ 已验证 |
| `0xA0` | EC 固件版本字符串（16 字节） | `16Q4EMS1.1100712` | ✅ 已验证 |
| `0xF4` | 风扇模式 | 见 §3 | ✅ 已验证 |
| `0xD4` | 风扇相关，用途未完全确定 | `0x70` | 🔵 候选 |
| `0xF2` | 性能模式，用途未完全确定 | `0x80` | 🔵 候选 |

正常运行时观测到会变化的寄存器（温度与风扇活动的证据）：
`0x68`、`0x71`、`0x89`、`0xC8`、`0xC9`、`0x99`、`0x9B`、`0xCB`、`0xCD`、`0xF9`。

转速可由周期寄存器换算：

| 风扇 | 周期寄存器 | 公式 |
|---|---|---|
| CPU | `0xCC` | `RPM = 478000 // value` |
| GPU | `0xCA` | `RPM = 478000 // value` |

> `//` 表示整除。计算前需防止除数为 0。

## 3. 风扇控制

转速百分比是**正向**的：值越大，风扇越快。早期曾观察到相反的关系，后来确认是读到了被
Cooler Boost 波及的一批无关寄存器（`0x01`、`0x02` 等），该结论已作废。

### 3.1 风扇模式 —— `0xF4`

| 值 | 模式 |
|---|---|
| `0x0C` | 自动 |
| `0x4C` | 基本 |
| `0x8C` | 高级（手动曲线生效） |

> 本机实际校准到的是 `0x0C`/`0x4C`/`0x8C`。公开的 `msi-ec`/`isw` 表中某些机型使用
> `0x0D`/`0x4D`/`0x8D`，两者不能想当然地互换，请在自己的硬件上验证。

### 3.2 一键强冷 —— `0x98`

| 值 | 状态 |
|---|---|
| `0x00` | 关 |
| `0x80` | 开（风扇拉满） |

### 3.3 手动风扇曲线（高级模式）

| 风扇 | 温度阈值 | 转速百分比 |
|---|---|---|
| CPU | `0x6A`–`0x6F` | `0x72`–`0x78` |
| GPU | `0x82`–`0x87` | `0x8A`–`0x90` |

曲线是六个温度点 → 转速的折线，对应六个温度阈值字节。校准记录中的转速区间跨了七个地址；
其中哪一个属于模式/头字节、哪一个是曲线点，在依赖最后一个字节之前应通过差异转储再确认。

## 4. 电池

- **读**：`0xEF` 保存充电停止阈值，`0xE4` 对应"充到 100% 停止"。
- **写（未验证）**：工作假设为 `值 = 百分比 + 0x80`，即 100% → `0xE4`（228），
  80% → `0xD0`（208）。该逻辑已在私有工具中实现，但撰写时尚未在硬件上确认。
  使用前请用差异转储验证。
- Quick Charge 3.0（USB 快充）是独立功能，不受此寄存器控制。

---

## 5. 校准方法

1. 以管理员权限加载 EC 访问驱动。
2. 全量转储 EC `0x00`–`0xFF` 作为基线。
3. 在官方软件中只改变一个设置（例如风扇从自动改为高级，或充电阈值从 100% 改为 80%）。
4. 再次转储并对比两份镜像。
5. 反复来回切换该设置，区分真正的目标寄存器和噪声。
6. 只记录可稳定复现的偏移，并标注机型、EC 固件和 BIOS 版本。

这与 GHelper 及其他厂商控制工具使用的差异法一致。由于 EC 布局随机型变化，
所有偏移都应视为机型限定。

---

## 6. 交叉验证与先行工作

以下开源项目公开了 MSI EC 布局，可用于对照。它们的寄存器表可能随机型和固件而不同：

- `msi-ec`（Linux 内核模块）
- `MControlCenter`（MCC）
- `isw`

与这些项目一致可提高可信度；不一致也并不自动说明某一方错误，因为布局本身就是机型相关的。
